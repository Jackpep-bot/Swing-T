## Expectation, stated before the run (the card's)

## Store
`config/prereg_b12.yaml` -> `data/live/replay_b12.duckdb` (batch 9's store plus 2016-24 Alpaca SIP bars for EFA, EEM,
VNQ, IEF, DBC, UUP; SPY and BIL from 2016-01-04). Price-only. Total-return figures, descriptive only, from
`data/live/replay_b12_tr.duckdb` (scripts/build_tr_store.py on replay_b12, built 2026-10-14).

## Rules
1. Signal day: the last session of each month; orders at the next session's open.
2. 12-month return = close on the signal day / close 252 sessions earlier - 1, for SPY, EFA and BIL.
3. If SPY's 12-month return is above BIL's: 100% in whichever of SPY and EFA has the higher one (SPY on a tie);
   otherwise 100% IEF (standing in for AGG; IEF is longer and fell more in 2022). Always fully invested.
4. Reading fixed here: the card's first signal day 2016-12-30 has only 251 earlier sessions in the store (bars start
   2016-01-04), so the first signal is 2017-01-31; the book holds SPY from the first session until the first switch.
   An order is placed only when the pick changes (a repeat pick holds the position; no trade).
5. No stops. Costs: `weights_book.simulate` with the per-symbol cost table.

## Windows and grading (docs/gates.md: Full-period test, Bill rate)
A 2017-01-01 .. 2024-10-04, B 2024-10-07 .. 2026-10-05, pooled 2017-01-01 .. 2026-10-05. PASS on either route: (1) in
both A and B, haircut Sharpe > 0, alpha against SPY > 0 and alpha t >= 2.241; or (2) the same in the pooled window with
alpha above zero in each of A and B. One trial (`prereg-b20`). Descriptive: number of switches, month-end signals per
ETF, the same orders on the total-return store, and the monthly excess-of-SPY correlation with batch 9's replica.
